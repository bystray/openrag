# «Извлечь заявки из базы знаний» — алгоритм и визуализация в Langflow

## 1. Как работает алгоритм сейчас

Полный пайплайн выполняется в бэкенде (сервис `LogisticsExtractionService`, эндпоинт `POST /logistics-requests/extract`). Точка входа — кнопка «Извлечь заявки из базы знаний» на странице логистических заявок в UI.

### Шаг 1. Параметры запуска

- **limit** — обработать только первые N кандидатов (опционально).
- **force** — переобработать уже сохранённые документы (иначе они пропускаются).
- **dry_run** — не писать в индекс, только вернуть результат извлечения.
- **filename** — обработать только один файл с указанным именем (опционально).

### Шаг 2. Поиск кандидатов в OpenSearch

- Индекс: **documents** (основной индекс чанков/документов).
- Условия:
  - `mimetype` = `application/pdf`;
  - в поле `text` есть хотя бы одна из ключевых фраз: «заявка на перевозку», «заявка», «маршрут», «место загрузки», «место разгрузки», «стоимость», «без НДС», «с НДС», «температурный режим».
- Результат: список уникальных **filename** (до 10000 или по limit).

### Шаг 3. Обработка каждого кандидата (цикл по filename)

Для каждого `filename`:

1. **Идемпотентность**  
   Если `force = false`, проверяется наличие записи в индексе **logistics_requests_structured** с `document_id = filename`. Если есть — документ пропускается (**skipped**).

2. **Сборка текста документа**  
   По индексу **documents** выбираются все чанки с данным `filename`, из поля `text` собирается список. Дубликаты и пустые строки удаляются, фрагменты склеиваются через `\n\n`. Итог — одна строка «полного текста» документа (до 120 000 символов для промпта).

3. **Извлечение структуры (LLM)**  
   - **Вариант A (без Langflow):** в коде формируется промпт (`build_logistics_extraction_prompt`): инструкция экстрактору, правила по НДС/дате/весу/температуре, список полей JSON, затем текст документа. Вызов OpenAI (или другого провайдера) `chat.completions` с `response_format: json_object`, температура 0.1. Ответ парсится как JSON.  
   - **Вариант B (с Langflow):** если задан `LANGFLOW_LOGISTICS_EXTRACT_FLOW_ID`, вместо прямого вызова LLM выполняется `POST /api/v1/run/{flow_id}`: в теле передаётся текст документа (`input_value`), в заголовках — `X-Langflow-Global-Var-DOCUMENT_ID` и `X-Langflow-Global-Var-FILENAME`. Ответ flow разбирается как JSON.

4. **Нормализация и валидация**  
   Приводятся форматы даты (YYYY-MM-DD) и веса (кг). Проверяется: `is_logistics_request` — boolean; для заявки (`true`) должны быть хотя бы маршрут/адреса, заказчик/перевозчик или цена/вес.

5. **Запись в индекс**  
   Если не `dry_run`: документ с полями `document_id`, `original_filename`, `processed_at` и всеми полями извлечения записывается в **logistics_requests_structured** с `id = document_id` (перезапись при повторном запуске с `force`).

### Шаг 4. Ответ API

Возвращается сводка: количество кандидатов, обработано, success/skipped/failed, и список элементов `{ filename, status }` по каждому файлу.

## 2. Какие части можно визуализировать в Langflow

В коде «визуализируемой» частью является только **шаг 3.3 — извлечение структуры через LLM**. Остальное (поиск кандидатов, сборка текста по чанкам, идемпотентность, валидация, запись в OpenSearch) остаётся в бэкенде.

Соответствие:

| Что в коде | В Langflow |
|------------|------------|
| Вход: один текст документа + document_id, filename | Chat Input (`input_value`) + глобальные переменные `DOCUMENT_ID`, `FILENAME` |
| Промпт: инструкция + правила + поля JSON + текст документа | Prompt Template (шаблон с подстановкой переменных и сообщения от Chat Input) |
| Вызов LLM (OpenAI, json_object, temperature 0.1) | Узел Language Model |
| Выход: один JSON-объект | Chat Output; бэкенд читает текст ответа и парсит JSON |

Бэкенд по-прежнему:
- находит кандидатов в **documents**;
- для каждого файла собирает текст из чанков;
- при наличии `LANGFLOW_LOGISTICS_EXTRACT_FLOW_ID` один раз за документ вызывает flow, передавая собранный текст и метаданные;
- валидирует ответ, нормализует дату/вес и пишет в **logistics_requests_structured**.

## 3. Как визуализировать процесс в Langflow

### 3.1. Создание flow

1. В проекте Langflow (например, Starter Project) нажмите **+ New Flow**.
2. Название: например, **Logistics Extraction Flow** (или «Извлечение логистических заявок»).

### 3.2. Узлы и связи

Добавьте цепочку из четырёх узлов:

1. **Chat Input**  
   Вход. Сюда бэкенд подставляет собранный текст документа в поле `input_value` при вызове `POST /api/v1/run/{flow_id}`.

2. **Prompt Template**  
   Шаблон промпта. В теле шаблона:
   - используйте глобальные переменные `{{DOCUMENT_ID}}` и `{{FILENAME}}` (бэкенд передаёт их в заголовках `X-Langflow-Global-Var-DOCUMENT_ID` и `X-Langflow-Global-Var-FILENAME`);
   - место для текста документа — сообщение от Chat Input (как в коде: инструкция + правила + «Текст документа: …» + ответ только JSON).

   Пример правил из кода:
   - НДС: «без НДС» → `vat_included = false`, `price_without_vat` = цена; «с НДС» → `vat_included = true`, `price_with_vat` = цена.
   - Дата: YYYY-MM-DD.
   - Вес: всегда в кг (10 тонн → 10000).
   - Температура: строка вида «-18» или «от +2 до +6».
   - Ответ — один JSON с полями: `is_logistics_request`, `request_number`, `request_date`, `route_from`, `route_to`, `loading_address`, `unloading_address`, `customer`, `carrier`, `cargo`, `weight_kg`, `temperature`, `vehicle`, `driver_name`, `driver_phone`, `price_without_vat`, `price_with_vat`, `vat_included`, `vat_rate`, `payment_terms`.

3. **Language Model** (OpenAI или другой)  
   Вызов LLM. Рекомендуется: вывод в формате JSON (json_object), температура ~0.1, достаточный `max_tokens`.

4. **Chat Output**  
   Выход. Бэкенд из ответа run забирает текст, при необходимости срезает обёртку ``` и парсит его как JSON.

Связи: **Chat Input** → **Prompt Template** → **Language Model** → **Chat Output**.

### 3.3. Глобальные переменные

В настройках flow должны быть доступны переменные **DOCUMENT_ID** и **FILENAME** (через окружение или из заголовков run). Бэкенд подставляет их при каждом вызове flow.

### 3.4. Подключение к OpenRAG

1. Сохраните flow в Langflow и скопируйте его **ID** (из URL или настроек).
2. В `.env` задайте:
   ```bash
   LANGFLOW_LOGISTICS_EXTRACT_FLOW_ID=<flow_id>
   ```
3. После перезапуска бэкенда кнопка «Извлечь заявки из базы знаний» будет для шага извлечения вызывать этот flow вместо прямого вызова LLM.

### 3.5. Формат ответа flow

Flow должен возвращать **один валидный JSON-объект**. Обязательное поле — `is_logistics_request` (boolean). Остальные поля — как в `EXTRACTION_FIELDS` в `logistics_extraction_service.py`. Бэкенд сам нормализует дату и вес и пишет в индекс.

### 3.6. Бэкап (по желанию)

Экспортируйте flow из Langflow (Download/Export) и сохраните JSON в репозиторий как `flows/logistics_extraction_flow.json`. ID в файле должен совпадать с `LANGFLOW_LOGISTICS_EXTRACT_FLOW_ID`. Тогда бэкапы и сброс flow для типа `logistics_extract` смогут использовать этот файл.
