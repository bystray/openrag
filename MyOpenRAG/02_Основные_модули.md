# Основные модули OpenRAG

## 1. Что это

Набор сервисов и слоёв бэкенда, реализующих загрузку, инжест, поиск, чат и коннекторы. Модули описаны по коду: `src/services/`, `src/api/`, `src/models/`, `src/connectors/`.

## 2. Зачем используется

Нужно для навигации по коду, добавления новых сценариев и исправления ошибок.

## 3. Как работает

### Frontend

- Next.js, страницы и компоненты (чат, база знаний, загрузка, настройки, коннекторы). Вызовы к Backend: `/upload_ingest`, `/search`, `/tasks`, `/settings`, `/chat`, `/connectors/*` и т.д.

### Backend API

- FastAPI приложение (`src/main.py`). Роуты: upload (в т.ч. router для upload_ingest), tasks, search, chat, langflow (files, ingest), documents, knowledge-filter, settings, connectors, auth, provider_health, docling (health). Внедрение зависимостей через `dependencies.py` (get_task_service, get_search_service, get_session_manager и др.).

### Ingestion service

- Реализован через **LangflowFileService** и **TaskService**. LangflowFileService: загрузка файла в Langflow (POST /api/v2/files), запуск ingestion flow (POST /api/v1/run/{flow_id}) с tweaks (DoclingRemote path, метаданные), опционально удаление файла из Langflow после инжеста. TaskService создаёт UploadTask и запускает процессор (LangflowFileProcessor), который для каждого файла вызывает upload_and_ingest_file.

### Embedding service

- Эмбеддинги создаются **внутри Langflow flow** (компоненты эмбеддингов в ingestion и chat flows). Backend не вызывает отдельный embedding API; размерности моделей и имена полей задаются в `config/settings.py` и `utils/embedding_fields.py` (OPENAI_EMBEDDING_DIMENSIONS, WATSONX_EMBEDDING_DIMENSIONS, get_embedding_field_name, ensure_embedding_field_exists).

### Search service

- **SearchService** (`src/services/search_service.py`). Принимает query, user_id, jwt_token, filters, limit, score_threshold. Получает opensearch_client по пользователю, строит запрос (в т.ч. kNN по полю chunk_embedding_* для выбранной модели), применяет фильтры (data_sources, document_types, owners, connector_types), возвращает результаты с чанками и скорами.

### Task processor

- **Процессоры** в `src/models/processors.py`: TaskProcessor (база), LangflowFileProcessor (файлы через Langflow), DocumentFileProcessor (традиционный путь без Langflow), LangflowConnectorFileProcessor (файлы из коннекторов), S3FileProcessor и др. Общая логика: проверка дубликатов (по hash или filename), вызов сервиса инжеста, обновление FileTask (status, result, error), учёт successful_files/failed_files в UploadTask.

### Langflow integration

- **LangflowFileService**: HTTP-запросы к Langflow (clients.langflow_request): upload, run_ingestion_flow, delete_user_file, upload_and_ingest_file. **FlowsService** — работа с flow (запуск чата, история). Конфиг: LANGFLOW_INGEST_FLOW_ID, LANGFLOW_CHAT_FLOW_ID, LANGFLOW_URL_INGEST_FLOW_ID, переменные окружения передаются в Langflow как global variables.

### Connectors

- **ConnectorService**, **LangflowConnectorService**, **ConnectionManager**. Коннекторы (Google Drive, OneDrive, SharePoint): OAuth, сохранение connection_id и токенов, список файлов, скачивание контента. При синхронизации файлы передаются в Langflow ingestion (process_connector_document) и индексируются в OpenSearch с метаданными коннектора.

## 4. Где используется в системе

- Frontend — точка входа пользователя.
- Backend API — единственная точка входа для всех операций.
- Ingestion — загрузка и папки (router), коннекторы (connector sync).
- Search — эндпоинт /search и инструмент агента (search_tool).
- Task processor — выполнение UploadTask при загрузке файлов и синхронизации коннекторов.
- Langflow integration — все вызовы инжеста и чата к Langflow.
- Connectors — UI и API коннекторов, фоновый sync.
