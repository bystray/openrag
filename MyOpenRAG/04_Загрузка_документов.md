# Загрузка документов

## 1. Что это

Процесс приёма файлов от пользователя (или коннектора), сохранения во временное хранилище и постановки в очередь на обработку через Langflow ingestion flow.

## 2. Зачем используется

Обеспечивает единую точку входа для добавления документов в базу знаний: файлы, папки, опции (настройки чанкинга, замена дубликатов, удаление файла из Langflow после инжеста).

## 3. Как работает

### Upload pipeline

- **Роут**: при `DISABLE_INGEST_WITH_LANGFLOW=false` используется `upload_ingest_router` (api/router.py). Принимает: file (список UploadFile), session_id, settings (JSON), tweaks (JSON), delete_after_ingest ("true"/"false"), replace_duplicates ("true"/"false"), create_filter.
- **Валидация**: разбор settings и tweaks из JSON; при ошибке — 400.
- **Временное сохранение**: для каждого файла содержимое читается (await upload_file.read()), имя нормализуется (пробелы и слэши заменяются), файл записывается во временную директорию (tempfile.gettempdir()). Формируется словарь temp_path → original_filename.
- **Создание задачи**: task_service.create_langflow_upload_task с user_id, file_paths, original_filenames, langflow_file_service, session_manager, jwt_token, owner_name, owner_email, session_id, tweaks, settings, delete_after_ingest, replace_duplicates. Возвращается task_id.
- **Ответ**: 202 с task_id, message, file_count, create_filter, filename (если один файл). При исключении временные файлы удаляются (safe_unlink).

### Temporary storage

- Файлы лежат в ОС-временной папке с именами без пробелов/слэшей. Пути передаются в TaskService и процессору. После обработки одного файла процессор может удалять временный файл (зависит от реализации); при падении всего запроса роутер удаляет все созданные temp_path.

### File processing

- Обработка выполняется **LangflowFileProcessor**. Для каждого пути: оригинальное имя берётся из original_filenames; для .txt в имени формируется langflow_filename с .md; для проверки дубликатов используется make_safe_storage_filename(langflow_filename). Проверка в OpenSearch по filename (check_filename_exists); при дубликате и replace_duplicates=false — FileTask FAILED; при replace_duplicates=true — delete_document_by_filename, затем продолжение. Файл читается в память, формируется file_tuple (filename, content, content_type); вызывается langflow_file_service.upload_and_ingest_file с owner, owner_name, owner_email, session_id, tweaks, settings, delete_after_ingest.

### Metadata extraction

- Метаданные задаются на уровне Backend и передаются в Langflow через заголовки и tweaks: owner (user_id), owner_name, owner_email, connector_type, FILENAME, MIMETYPE, FILESIZE, SELECTED_EMBEDDING_MODEL, DOCUMENT_ID, SOURCE_URL, ALLOWED_USERS, ALLOWED_GROUPS. В flow они попадают в глобальные переменные и в компонент OpenSearch при индексации.

## 4. Где используется в системе

- api/router.py — upload_ingest_router, _langflow_upload_ingest_task.
- api/upload.py — альтернативные эндпоинты (upload_context, upload_path, upload_options, upload_bucket) при традиционном сценарии.
- api/langflow_files.py — upload_user_file, upload_and_ingest_user_file, run_ingestion.
- services/task_service.py — create_langflow_upload_task, create_custom_task.
- models/processors.py — LangflowFileProcessor.process_item.
- services/langflow_file_service.py — upload_user_file, run_ingestion_flow, upload_and_ingest_file.

## 5. Связанные компоненты

TaskService, LangflowFileService, LangflowFileProcessor, SessionManager, OpenSearch (проверка дубликатов и удаление по filename), DocumentService (при традиционном upload).
