# Архитектура системы OpenRAG

## 1. Что это

Архитектура OpenRAG — набор сервисов и потоков данных: фронтенд, бэкенд, Langflow, Docling, OpenSearch и система задач. База знаний хранится в OpenSearch; инжест и чат выполняются через Langflow flows.

## 2. Зачем используется

Понимание архитектуры нужно для развёртывания, отладки, расширения (новые коннекторы, модели эмбеддингов, стратегии поиска) и анализа ошибок.

## 3. Как работает

### Frontend (Next.js)

- UI: чат, база знаний (просмотр документов/чанков), загрузка файлов и папок, настройки, коннекторы.
- Обращается к Backend по API (загрузка, поиск, чат, задачи, настройки).

### Backend (FastAPI)

- Единая точка входа для API. Инициализирует OpenSearch, Langflow-клиент, Docling-клиент, сервисы (Task, Search, Chat, Document, Connector).
- Роутинг загрузки: при `DISABLE_INGEST_WITH_LANGFLOW=false` (по умолчанию) запросы на инжест идут в TaskService и далее в Langflow; иначе — в традиционный upload (document_service).

### Langflow

- Контейнер с Langflow. Получает из окружения переменные: OPENSEARCH_URL, OPENSEARCH_PASSWORD, OPENSEARCH_INDEX_NAME и др. (LANGFLOW_VARIABLES_TO_GET_FROM_ENVIRONMENT).
- Ingestion flow: приём файлов (DoclingRemote), парсинг, SplitText, эмбеддинги, запись в OpenSearch.
- Chat flow: запрос → эмбеддинг → поиск по OpenSearch → контекст → LLM.

### Docling (Docling Serve)

- Сервис парсинга документов. API: POST `/v1/convert/file`, ответ — JSON с полем `document.json_content` (структурированный документ/блоки).
- Вызывается из Langflow flow (компонент DoclingRemote) или при альтернативном пайплайне.

### OpenSearch

- Хранит индекс документов (по умолчанию `documents`). В индексе: поля text, filename, mimetype, page, chunk_embedding_* (knn_vector), embedding_model, owner, metadata и др.
- Backend и Langflow подключаются к OpenSearch по URL/учётным данным из конфигурации.

### Task system

- TaskService хранит задачи по user_id (task_id → UploadTask). UploadTask содержит file_tasks (путь/идентификатор → FileTask).
- Обработка: процессор (LangflowFileProcessor, DocumentFileProcessor, LangflowConnectorFileProcessor и др.) обрабатывает каждый элемент; семафор ограничивает число одновременных обработок (MAX_WORKERS).
- Статусы: PENDING, RUNNING, COMPLETED, FAILED. Периодическая очистка старых задач (CLEANUP_INTERVAL_SECONDS).

### Connectors

- Google Drive, OneDrive, SharePoint. OAuth, хранение токенов, получение списка файлов и контента. Синхронизация через ConnectorService и LangflowConnectorService — файлы обрабатываются Langflow ingestion flow и пишутся в OpenSearch с метаданными (connector_type, document_id и т.д.).

## 4. Где используется в системе

Архитектура задаёт границы компонентов: все запросы от UI идут в Backend; инжест и чат делегируются Langflow; хранилище — OpenSearch; фоновые загрузки — через TaskService и процессоры.

## 5. Связанные компоненты

Frontend, Backend, Langflow, Docling, OpenSearch, TaskService, LangflowFileService, SearchService, ChatService, ConnectorService, SessionManager.
