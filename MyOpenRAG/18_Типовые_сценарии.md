# Типовые сценарии

## 1. Что это

Типовые сценарии использования OpenRAG: индексация PDF, индексация документации (URL), индексация базы знаний (множество файлов/папка). Описание потока и задействованных компонентов.

## 2. Зачем используется

Чтобы воспроизводить и отлаживать стандартные кейсы и проектировать похожие сценарии.

## 3. Как работает

### Индексация PDF

- Пользователь загружает один или несколько PDF через Add Knowledge → File. Frontend отправляет POST на роут загрузки (upload_ingest) с файлами. Backend сохраняет во временные файлы, создаёт UploadTask с LangflowFileProcessor, возвращает task_id. Процессор для каждого файла: проверка дубликата по filename (safe name), при необходимости замена (replace_duplicates); upload в Langflow Files API; run_ingestion_flow с tweaks DoclingRemote-Dp3PX.path = [path]. В flow: Docling парсит PDF (Docling Serve /v1/convert/file), выход — структурированные блоки; SplitText режет на чанки; эмбеддинги; запись в OpenSearch. После успеха файл удаляется из Langflow (delete_after_ingest). Статус задачи доступен по GET /tasks/{task_id}. Большие PDF: увеличить LANGFLOW_TIMEOUT и INGESTION_TIMEOUT при таймаутах.

### Индексация документации (URL)

- Сценарий «документация по URL»: пользователь задаёт URL (например DEFAULT_DOCS_URL), глубина обхода (crawl_depth). Backend создаёт задачу через create_langflow_url_upload_task с LangflowUrlProcessor. Процессор вызывает langflow_file_service.run_url_ingestion_flow(docs_url, crawl_depth, ...). Flow (LANGFLOW_URL_INGEST_FLOW_ID) выполняет обход URL, загрузку страниц, парсинг и инжест в OpenSearch. При отсутствии flow ID возможен импорт из flows/openrag_url_mcp.json. Конфиг: DEFAULT_DOCS_INGEST_SOURCE=url, DEFAULT_DOCS_URL, DEFAULT_DOCS_CRAWL_DEPTH.

### Индексация базы знаний (папка / множество файлов)

- Пользователь выбирает папку или несколько файлов. Frontend может предварительно проверять дубликаты (GET /documents/check-filename для части файлов) и отправлять только новые или все с флагом replace_duplicates. Один запрос upload_ingest с несколькими файлами: Backend создаёт одну UploadTask с несколькими FileTask. Обработка параллельно с ограничением MAX_WORKERS (семафор в TaskService). Каждый файл обрабатывается как в сценарии «индексация PDF». Итог: множество чанков в OpenSearch с разными filename; фильтрация при поиске по data_sources (filename). При большом числе файлов учитывать UPLOAD_BATCH_SIZE и лимиты времени ответа; статус смотреть по task_id.

## 4. Где используется в системе

- PDF: api/router.py, task_service.create_langflow_upload_task, LangflowFileProcessor, langflow_file_service.upload_and_ingest_file, run_ingestion_flow; flow DoclingRemote, SplitText, OpenSearch.
- URL: task_service.create_langflow_url_upload_task, LangflowUrlProcessor, run_url_ingestion_flow; flow openrag_url_mcp; config DEFAULT_DOCS_*.
- Папка/много файлов: тот же upload_ingest и LangflowFileProcessor; frontend — выбор папки, батчи или один запрос с несколькими файлами; documents/check-filename, replace_duplicates.

## 5. Связанные компоненты

Router, TaskService, LangflowFileProcessor, LangflowFileService, LangflowUrlProcessor, ingestion flow, URL ingestion flow, api/documents (check-filename).
