# Потоки данных OpenRAG

## 1. Что это

Последовательности преобразования данных: от загрузки документа до появления чанков в OpenSearch и от пользовательского запроса до ответа LLM.

## 2. Зачем используется

Нужно для проектирования новых пайплайнов, отладки и понимания, на каком этапе возникают ошибки.

## 3. Как работает

### Поток загрузки документа

1. **Загрузка**: пользователь выбирает файлы/папку → Frontend отправляет POST на роут загрузки (например `/upload_ingest`) с файлами и опциями (settings, tweaks, replace_duplicates, delete_after_ingest).
2. **Временное хранилище**: Backend сохраняет файлы во временную директорию (tempfile), формирует список путей и оригинальных имён.
3. **Создание задачи**: TaskService.create_langflow_upload_task создаёт UploadTask и FileTask для каждого файла, возвращает task_id.
4. **Обработка**: воркер берёт FileTask, LangflowFileProcessor для каждого файла: проверка дубликата по filename (check_filename_exists в OpenSearch), при необходимости delete_document_by_filename; чтение файла, формирование file_tuple (имя, содержимое, content_type); вызов LangflowFileService.upload_and_ingest_file (upload → run_ingestion_flow → при delete_after_ingest удаление файла из Langflow).
5. **Парсинг**: внутри Langflow flow файл передаётся в Docling (DoclingRemote): конвертация в структурированный JSON (блоки).
6. **Создание блоков/чанков**: компонент разбиения (например SplitText) режет текст на чанки с заданными chunk_size, chunk_overlap, separator (настраиваются через tweaks/settings).
7. **Эмбеддинги**: компонент эмбеддингов получает текст чанков и модель (SELECTED_EMBEDDING_MODEL из заголовков/глобальных переменных), создаёт векторы.
8. **Индексация**: компонент OpenSearch в flow записывает документы в индекс: text, filename, mimetype, page, chunk_embedding_*, embedding_model, owner, metadata и др. Поле имени файла в индексе — нормализованное (safe storage filename).
9. **Обновление задачи**: FileTask переводится в COMPLETED или FAILED, обновляются счётчики successful_files/failed_files в UploadTask.

### Поток поиска и ответа (RAG)

1. **Запрос**: пользователь вводит запрос в чат или вызывает поиск.
2. **Эмбеддинг запроса**: в Langflow chat flow запрос преобразуется в вектор той же моделью, что и чанки.
3. **Векторный поиск**: kNN по полю chunk_embedding_* в OpenSearch с фильтрами (owner, data_sources и т.д.), limit и score_threshold.
4. **Получение чанков**: из OpenSearch возвращаются документы с text, filename, score.
5. **Сборка контекста**: выбранные чанки объединяются в контекст для LLM.
6. **Ответ LLM**: промпт агента + контекст передаётся в LLM; ответ возвращается пользователю.

## 4. Где используется в системе

- Загрузка: api/router.py (upload_ingest), api/langflow_files.py, services/task_service.py, models/processors.py (LangflowFileProcessor), services/langflow_file_service.py.
- Парсинг и чанки: внутри Langflow flow (DoclingRemote, SplitText).
- Эмбеддинги и индексация: компоненты Langflow flow, config/settings.py, utils/embedding_fields.py, utils/opensearch_queries.py.
- Поиск и ответ: services/search_service.py, services/chat_service.py, Langflow chat flow.

## 5. Связанные компоненты

TaskService, LangflowFileService, LangflowFileProcessor, Docling, OpenSearch, SearchService, ChatService, FlowsService.
