# Расширение системы

## 1. Что это

Способы добавления нового функционала: отдельный ingestion pipeline, новая модель эмбеддингов, новый коннектор, новая стратегия retrieval. Описание по текущей структуре кода.

## 2. Зачем используется

Чтобы расширять OpenRAG без полной переработки: подключать новые источники данных, модели и стратегии поиска.

## 3. Как работает

### Добавление ingestion pipeline

- **Вариант A (Langflow)**: создать новый flow в Langflow (или клонировать существующий), настроить компоненты (источник файлов, Docling/другой парсер, SplitText, эмбеддинги, OpenSearch). Зарегистрировать flow в Backend через новую переменную окружения (например LANGFLOW_CUSTOM_INGEST_FLOW_ID). В TaskService добавить метод create_custom_ingest_task и процессор, который вызывает run с нужным flow_id (аналогично LangflowFileProcessor, но с другим flow_id и при необходимости другими tweaks). Роут или флаг выбора пайплайна — по необходимости.
- **Вариант B (без Langflow)**: при DISABLE_INGEST_WITH_LANGFLOW=true используется традиционный путь (DocumentService, process_file_common). Можно реализовать альтернативный процессор (наследник TaskProcessor), вызывающий docling_client.convert_file, собственный чанкинг и вызов эмбеддингов (вне Langflow — нужен отдельный сервис эмбеддингов или вызов провайдера), запись в OpenSearch через opensearch_client. Зарегистрировать процессор в create_custom_task.

### Добавление embedding-модели

- Добавить размерность модели в config/settings.py: OPENAI_EMBEDDING_DIMENSIONS или WATSONX_EMBEDDING_DIMENSIONS (или отдельный словарь для провайдера). Для Ollama размерность определяется через get_embedding_dimensions (probing). В Langflow flow добавить/настроить компонент эмбеддингов для новой модели. При первом использовании ensure_embedding_field_exists создаст поле chunk_embedding_{normalized_name} в индексе. В config_manager (knowledge.embedding_model) добавить возможность выбора новой модели в UI/API настроек.

### Добавление коннектора

- Реализовать класс коннектора (наследник BaseConnector в connectors/base.py): методы аутентификации (OAuth), list_files, get_file_content, возврат ConnectorDocument. Реализовать OAuth endpoints (как в google_drive/oauth.py, onedrive/oauth.py). Зарегистрировать коннектор в ConnectionManager (тип connector_type). В api/connectors.py логика sync уже общая; при необходимости добавить маппинг connector_type → класс. Синхронизация через LangflowConnectorService.process_connector_document или аналог — без изменений, если формат ConnectorDocument совместим.

### Добавление retrieval-стратегии

- **В Langflow**: в chat flow добавить ветку или компонент (например гибридный поиск: вектор + keyword). Результат по-прежнему — список чанков для контекста.
- **В Backend**: в SearchService добавить метод (например search_hybrid) или параметр strategy; строить другой body запроса к OpenSearch (bool query с сочетанием kNN и term/match). API /search расширить параметром strategy или отдельным эндпоинтом. Конфиг: выбор стратегии в настройках (knowledge или agent).

## 4. Где используется в системе

- Точки расширения: TaskService.create_custom_task, модели процессоров (processors.py), config/settings (размерности, flow ID), config_manager (embedding_model, провайдеры), connectors/base.py и connection_manager, SearchService, api/search.

## 5. Связанные компоненты

TaskService, processors, LangflowFileService, config/settings, config_manager, connectors/base, ConnectionManager, SearchService, embedding_fields.
