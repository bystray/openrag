# Архитектурные ограничения

## 1. Что это

Ограничения и допущения архитектуры OpenRAG, связанные с выбором Docling, Langflow, OpenSearch и моделей эмбеддингов. Понимание ограничений нужно для планирования масштабирования и обхода узких мест.

## 2. Зачем используется

Чтобы не проектировать сценарии, противоречащие возможностям системы, и знать границы расширяемости.

## 3. Как работает

### Docling

- Зависимость от внешнего сервиса (Docling Serve): при недоступности инжест файлов через flow падает. Поддерживаемые форматы задаются Docling (PDF, Office, HTML и др.); не все форматы могут давать качественный текст. OCR опционален (DOCLING_OCR_ENGINE); производительность и качество зависят от объёма и сложности документа. Один запрос конвертации — один файл; батчинг на стороне Backend (несколько файлов в одной задаче обрабатываются по одному в процессоре).

### Langflow

- Инжест и чат завязаны на готовые flow: смена логики парсинга/чанкинга/эмбеддингов требует правки flow в Langflow или загрузки нового flow и смены LANGFLOW_INGEST_FLOW_ID/LANGFLOW_CHAT_FLOW_ID. Глобальные переменные и заголовки — основной способ передачи параметров из Backend; не все компоненты могут их использовать одинаково. Таймауты: LANGFLOW_TIMEOUT и INGESTION_TIMEOUT ограничивают длительность одного запроса/файла. Файлы после инжеста по умолчанию удаляются из Langflow (нет «архива» загруженных файлов в Langflow).

### OpenSearch

- Один индекс по умолчанию (documents) для всех чанков; мультитенантность через поле owner и фильтры при поиске. Размерность вектора фиксирована для каждой модели; смена модели эмбеддингов требует нового поля (chunk_embedding_*) и переиндексации для полного использования новой модели. KNN-параметры (ef_construction, m) заданы в маппинге; смена требует обновления маппинга и переиндексации. Масштабирование: один индекс, number_of_shards/replicas заданы при создании; горизонтальное масштабирование кластера OpenSearch — отдельная тема.

### Embeddings

- Модель эмбеддингов задаётся в настройках (knowledge.embedding_model); все новые чанки индексируются с этой моделью. Смешение моделей в одном индексе возможно за счёт разных полей chunk_embedding_*, но поиск в SearchService идёт по одному выбранному полю (текущая модель); для поиска по другой модели нужна доработка (выбор поля по модели в запросе). Размерности должны быть известны (словарь или Ollama probing); неизвестная модель использует VECTOR_DIM по умолчанию, что может дать несовместимость с реальной размерностью.

## 4. Где используется в системе

- Ограничения Docling: utils/docling_client, api/docling, Langflow DoclingRemote; конфиг DOCLING_SERVE_URL, INGESTION_TIMEOUT.
- Ограничения Langflow: services/langflow_file_service, config/settings LANGFLOW_*, flow ID и глобальные переменные.
- Ограничения OpenSearch: config/settings INDEX_BODY, utils/embeddings create_dynamic_index_body, utils/embedding_fields ensure_embedding_field_exists; SearchService — один embedding_field на запрос.
- Ограничения эмбеддингов: config/settings размерности, utils/embeddings get_embedding_dimensions.

## 5. Связанные компоненты

Docling, Langflow, OpenSearch, embedding_fields, SearchService, config/settings.
